# SimpleStore → Go: A Faithful-Port Backend Course (~2 weeks)

## Context

SimpleStore is a .NET 10 / Aspire monolith. It has one Postgres database (`storedb`) and two web apps:
- **SimpleStore.Web**: the storefront, on :5200.
- **SimpleStore.Admin**: the dashboard, on :5194.

The goal is to rebuild it in Go **as close to the C# source as possible**. It's a learning exercise and a **starting point**: later iterations will solve its problems one by one (and eventually split it into microservices). That's why we **deliberately keep the original behavior, quirks included**, and record every quirk in a **Future Backlog** (§5) instead of fixing it now.

**Who builds what:**
- **You** write the entire Go backend by following this course. Claude does not write backend code.
- **Claude** writes the frontend (HTML/CSS/JS), copying the look and the pages of the C# app.

The only structural change is that the C# controllers return HTML, while the Go backend exposes a **JSON API** and Claude's static pages call it. Everything else (data, rules, flows, cookies, ports, quirks) matches the original.

## 1. Fidelity rules: what is copied, and what changes by necessity

### Copied 1:1
| Area | C# source | Go port |
|---|---|---|
| Orchestration | Aspire: postgres + pgweb + `storedb`. Web and Admin `WaitFor(storeDb)` | Compose: `postgres` + `sosedoff/pgweb`. `store` and `admin` both `depends_on: postgres: service_healthy` (admin does **not** wait for store, the same as the C#) |
| Ports | Web :5200, Admin :5194 | store :5200, admin :5194 |
| Migrations + seed | Only Web runs `MigrateAsync` + `SeedAsync` + `SeedIdentityAsync` at startup | Only `cmd/store` runs migrate + seed |
| Seed data | 4 categories, 10 products (image paths `/images/products/*.jpg`, which **don't exist**), demo user `demo@simplestore.local` / `Demo123!` (FullName "Demo User", EmailConfirmed) | identical, including the missing images |
| Money | `decimal` / `numeric(18,2)` | `numeric(18,2)` in the DB. `shopspring/decimal` in Go (the closest thing to C# `decimal`). JSON numbers like `199.99` |
| IDs | int identity for domain tables. User ID is a **string GUID** | `integer GENERATED BY DEFAULT AS IDENTITY`. `users.id TEXT` (UUID string) |
| Foreign keys | products→categories **CASCADE**, order_items→orders **CASCADE**, order_items→products **CASCADE**, `orders.user_id` **has no FK**, passkeys→users CASCADE | identical |
| Indexes | `products(category_id)`, `order_items(order_id)`, `order_items(product_id)`, unique `normalized_user_name`, non-unique `normalized_email` | identical |
| User fields | `IdentityUser` + `FullName`. Used: Id, UserName (= email), Normalized*, Email, EmailConfirmed, PasswordHash, SecurityStamp, PhoneNumber, LockoutEnd, LockoutEnabled, AccessFailedCount | a `users` table with the same columns (snake_case) |
| Password hashing | Identity v3: PBKDF2-HMAC-SHA512, 100k iterations, 128-bit salt, 256-bit subkey | stdlib **`crypto/pbkdf2`** with the same parameters. Stretch goal: the same byte format, so C# hashes would verify in Go |
| Password rules | min length 6, requires a digit, **requires lowercase** (Identity default), no uppercase or symbol needed. Register: FullName required ≤100, Password 6–100, ConfirmPassword must match, Email valid | identical validator |
| Cart session | `AddSession` + `AddDistributedMemoryCache`: **in-memory**, 30-min idle, HttpOnly, essential. Cart stored as JSON under key `shopping_cart`. **Lost on restart** | `alexedwards/scs/v2` with the **in-memory store** (`memstore`), 30-min idle, HttpOnly. Cart stored as JSON under `shopping_cart` |
| Auth | Identity application cookie: **a self-contained encrypted ticket** (no server store), sliding expiry 14 days, persistent only with "Remember me" | a **second cookie**: an AES-GCM-encrypted payload (stdlib `crypto/aes` + `crypto/cipher`) holding userID + security stamp + expiry. 14-day sliding. Persistent (`Max-Age`) only if rememberMe, otherwise a browser-session cookie. Key comes from env (≈ Data Protection keys) |
| Lockout | checked **only at password sign-in** ("This account is locked."). `lockoutOnFailure: false`, so failed attempts are never counted | identical |
| Passkeys | Identity v3 passkeys: register (named), list, delete, discoverable login. Table `(credential_id bytea PK, user_id, data jsonb)`. Authenticator timeout 2 min | `go-webauthn/webauthn` with the same table shape (`data jsonb` holds the credential) and a 2-min timeout. Challenge kept in the cart session |
| CSRF | Razor Pages POSTs (login, register, logout, profile, passkeys) + `[ValidateAntiForgeryToken]` on checkout. **Cart POSTs are NOT protected** | `http.CrossOriginProtection` applied **per-route** to the same set. Cart routes left unprotected |
| Admin auth | **None** | **None** (no login, no roles) |
| Health | `/health` (all checks, including the Npgsql DbContext check) and `/alive` (self). **Development only** | `/health` (DB ping) and `/alive`. Registered only when `APP_ENV=Development` |
| Telemetry | OpenTelemetry logs + traces + metrics via OTLP, when `OTEL_EXPORTER_OTLP_ENDPOINT` is set | OTel Go SDK (`otelhttp`, `otelpgx`, slog bridge) under the same env-var rule. Compose adds the **standalone Aspire Dashboard** container to view it |
| Errors | non-dev: exception handler + HSTS + HTTPS redirect | recover middleware → 500 JSON. HTTPS/HSTS are left to a reverse proxy (explained on Day 11) |

### Changed by necessity (documented, not "improvements")
- **JSON API + static frontend** instead of server-rendered views. Responses mirror the C# view models' fields.
- **snake_case table and column names** instead of EF's quoted PascalCase (Go/Postgres convention). The column set is unchanged.
- **The 5 unused Identity tables** (Roles, RoleClaims, UserClaims, UserLogins, UserTokens) are **not created**, because no feature reads or writes them. Add them later if a feature needs them.
- Service discovery / HTTP-client resilience from ServiceDefaults is skipped, because neither app makes outbound HTTP calls.

## 2. Architecture & layout

```
Browser ─► cmd/store :5200  ── /api/v1/* (your Go)  +  /* static (Claude's web/store)
Browser ─► cmd/admin :5194  ── /api/v1/* (your Go)  +  /* static (Claude's web/admin)
                 └──────────────┬──────────────┘
                     Postgres storedb  (+ pgweb, + Aspire Dashboard for OTel)
```
Same origin for the API and the pages, so cookies just work with no CORS.
**Layering rule:** handlers (HTTP/JSON) → services (rules) → sqlc queries → Postgres. This is the same as Controllers → Services → DbContext.

```
golang/                       (on branch go-port from main)
  go.mod  compose.yaml  Makefile  sqlc.yaml  .env.example  Dockerfile
  cmd/store/main.go   cmd/admin/main.go
  internal/
    config/       env → Config (APP_ENV, DATABASE_URL, HTTP_ADDR, AUTH_KEY, OTEL_*)
    database/     pool.go, migrate.go, seed.go, migrations/*.sql, queries/*.sql, sqlcdb/ (generated)
    platform/     health.go, telemetry.go, logging.go          ← ServiceDefaults equivalent
    identity/     password.go (PBKDF2), authcookie.go (AES-GCM), users.go, passkeys.go
    catalog/ cart/ order/                                      ← Web/Services equivalents
    httpx/        json.go, errors.go, validator.go, middleware.go
    storefront/   handlers + routes                             ← Web Controllers + Identity pages
    adminapi/     handlers + routes                             ← Admin Razor components' @code
  web/store/  web/admin/      ← Claude's frontend, embedded with embed.FS
```

**C# → Go cheat-sheet**
| C# | Go |
|---|---|
| DI container, `AddScoped` | build structs in `main`, pass them as fields |
| `async/await`, `CancellationToken` | blocking calls, a goroutine per request, `r.Context()` |
| exceptions | `error` values, `errors.Is`, sentinel errors |
| `decimal` | `decimal.Decimal` |
| filters / middleware / `[Authorize]` | `func(http.Handler) http.Handler` |
| `User` claims | user put in `context.Context` by middleware |
| `Include()` | `JOIN` / second query with `= ANY($1)` |
| `SaveChangesAsync()` | one statement, or `Begin → WithTx → Commit` |
| DataAnnotations | hand-written validator |
| `TempData` message | returned in the JSON (`message`). The frontend shows it |

## 3. API contract (frozen Day 1). Field names mirror the C# models

Conventions:
- camelCase JSON. Money is a JSON number (`199.99`). Times are RFC 3339.
- Error shape: `{"error":{"code","message","fields":{...}}}`.
- 400 malformed, 401 not signed in (the frontend sends you to `/login?returnUrl=`), 404, 409, 422 validation, 500.

### Storefront (:5200/api/v1)
| Route | C# origin | Behavior (faithful) |
|---|---|---|
| `GET /categories` | `GetCategoriesAsync` | all categories `{id,name,description}` |
| `GET /products?categoryId=&search=` | `CatalogController.Index` | includes `category{id,name}`. Search is **case-sensitive `LIKE`** on name or description (EF `Contains` on Npgsql) |
| `GET /products/{id}` | `Details` | product + category, or 404 |
| `GET /cart` | `CartController.Index`, CartCount | `{items:[{productId,productName,unitPrice,quantity,imageUrl,totalPrice}],count,total}` |
| `POST /cart/items` `{productId,quantity=1}` | `Add` | if already in the cart: quantity += n (**no checks**). Else: if the product exists, add it with its current price; if not, do nothing. Returns `{message:"Item added to cart!"}` even if nothing was added |
| `PUT /cart/items/{productId}` `{quantity}` | `Update` | ≤0 removes. Unknown product is a no-op |
| `DELETE /cart/items/{productId}` | `Remove` | |
| `POST /account/register` `{email,fullName,password,confirmPassword}` | Register page | creates the user (EmailConfirmed=true), signs in (non-persistent). Duplicate username → 422 with the Identity-style message |
| `POST /account/login` `{email,password,rememberMe}` | Login page | 401 "Invalid email or password." / 423 "This account is locked." |
| `POST /account/logout` | Logout page | clears the auth cookie (the cart session stays) |
| `GET /account/me` | layout `User.Identity.Name` | `{id,userName,email,fullName}` or 401 |
| `GET/PUT /account/profile` `{fullName}` 🔒 | Manage/Index | required, ≤100. If changed: update + refresh the cookie. `{message:"Profile updated."}` |
| `GET /account/passkeys` 🔒 | Manage/Passkeys | list `{credentialId(base64url),name,createdAt}` |
| `POST /account/passkeys/creation-options` 🔒 | `OnPostCreationOptions` | WebAuthn creation options (displayName = FullName or userName) |
| `POST /account/passkeys` `{credential,name}` 🔒 | `OnPostRegister` | `{ok:true}` or 400 `{error}` |
| `DELETE /account/passkeys/{credentialId}` 🔒 | `OnPostDelete` | "Passkey removed." / "Passkey not found." |
| `POST /account/passkey-login/options` | `OnPostPasskeyRequestOptions` | discoverable request options |
| `POST /account/passkey-login?returnUrl=` `{credential}` | `OnPostPasskeyAssert` | signs in. `{redirectTo}` (local URLs only) or 400 "Passkey sign-in failed." |
| `GET /checkout` 🔒 | `Checkout` GET | `{cartItems,total,fullName,email}` prefilled. An empty cart → `{cartEmpty:true}` (the frontend goes to the cart, like `RedirectToAction`) |
| `POST /orders` `{fullName,email,shippingAddress,city,postalCode}` 🔒 | `Checkout` POST | all required + email format. Creates the order from the **cart prices as stored**, status "Pending", total = Σ. **Only shippingAddress is saved**. **No stock check or decrement. An empty cart is not rejected.** Clears the cart → 201 `{id}` |
| `GET /orders` 🔒 | `Orders.Index` | newest first, with items + product |
| `GET /orders/{id}` 🔒 | `Details` / `Confirmation` | only if `user_id` matches, else 404 |

### Admin (:5194/api/v1). No auth, as in the source
| Route | C# origin | Behavior |
|---|---|---|
| `GET /dashboard` | Home.razor | `{customerCount,categoryCount,productCount,orderCount,pendingOrders,completedOrders (=Delivered),totalRevenue}`, as **7 separate queries** like the source |
| `GET /categories` | Categories.razor | ordered by name, with `productCount` |
| `POST /categories`, `PUT /categories/{id}` `{name,description}` | `SaveAsync` | name required ("Category name is required."), values trimmed |
| `DELETE /categories/{id}` | `DeleteAsync` | does nothing if missing or if it has products. The API returns 404 / 409 so the UI can explain (the button is disabled in the UI, as in the source) |
| `GET /products` | Products.razor | ordered by name, with `categoryName` |
| `POST /products`, `PUT /products/{id}` `{name,description,price,stock,imageUrl,categoryId}` | `SaveAsync` | requires name non-blank and categoryId>0 ("Product name and category are required."). Trimmed. A blank imageUrl becomes `/images/products/placeholder.jpg`. **Price and stock are not validated** |
| `DELETE /products/{id}` | `DeleteAsync` | **cascades to order_items** (the FK is CASCADE) |
| `GET /orders` | Orders.razor | newest first: `{id,customerLabel (FullName → Email → UserId),orderDate,itemCount (Σ quantity),totalAmount,shippingAddress,status}` |
| `PUT /orders/{id}/status` `{status}` | `SaveStatusAsync` | must be one of Pending, Processing, Shipped, Delivered, Cancelled (the dropdown list). "Order #N updated to X." |
| `GET /customers` | Customers.razor | all users ordered by email: `{id,fullName,email,phoneNumber,isLocked (lockoutEnd>now),orderCount}` |
| `PUT /customers/{id}` `{fullName}` | `SaveCustomerAsync` | trimmed. "Updated {email}." |
| `POST /customers/{id}/toggle-lock` | `ToggleLockAsync` | locked → `lockout_end=NULL`, else now+100y. "Locked/Unlocked {email}." **Existing logins stay valid** (the same as the source) |

## 5. Future Backlog: quirks preserved now, to solve in later iterations
1. The admin has **no authentication or authorization**.
2. Checkout uses **stale cart prices**, never **checks or decrements stock**, and **accepts an empty cart** (on POST).
3. Checkout **discards City and Postal Code**.
4. Add-to-cart doesn't validate quantity (negative or huge) and responds with success even for a missing product.
5. **Deleting a product cascades to order_items**, silently rewriting order history. Category→product cascade is guarded only by the UI.
6. `orders.user_id` has **no foreign key**, and there's no index on it.
7. Cart **POSTs have no CSRF protection**.
8. Locking a customer **doesn't end their existing session**. No failed-login lockout.
9. The cart lives **in process memory**: lost on restart, and it can't scale to more than one instance.
10. The admin can start **before migrations have run** (it only waits for Postgres).
11. Search is **case-sensitive** and unindexed.
12. Product **images don't exist** (404).
13. The dashboard makes 7 round-trips. Admin list pages aren't paginated.
14. Production exception handling points to a **non-existent `/Home/Error`** in the C# app (the Go version just returns 500 JSON).
15. Architecture: a modular-monolith boundary cleanup (per-module tables, no cross-module joins), as the step toward microservices.

## D1.3 Concepts you must understand before writing code (the lecture)

### 1. What actually travels over the wire
Run `curl -v http://example.com` and look at it. A request is plain text:
```
GET /products/3?x=1 HTTP/1.1      ← method, path + query, protocol
Host: example.com                  ← headers (key: value)
Accept: */*
                                   ← blank line, then an optional body
```
A response is a status line (`HTTP/1.1 200 OK`), headers, a blank line, and the body. **Every request is independent.** The server remembers nothing between requests unless you add cookies or sessions (Day 6). A "web server" is just a long-running program that accepts TCP connections, parses this text, calls your code, and writes text back.

### 2. `http.Handler`: the whole of Go web development rests on one method
```go
type Handler interface { ServeHTTP(w http.ResponseWriter, r *http.Request) }
```
- `r` is the parsed request (method, URL, headers, body, `Context()`).
- `w` is how you build the response. **Order matters:** set headers via `w.Header().Set(...)`, then `w.WriteHeader(status)` (once), then `w.Write(body)`. If you `Write` without calling `WriteHeader`, Go sends **200** automatically. Headers set after the first `Write` are **silently ignored**.
- `http.HandlerFunc` is a type that turns an ordinary `func(w, r)` into a `Handler`. This adapter pattern is everywhere.
- In C# terms, a controller action, a middleware, and a whole app are all "something that handles a request". In Go they are all literally `http.Handler`. A router is a Handler that picks another Handler. Middleware is a Handler that wraps a Handler.

### 3. `ServeMux`: the router (Go 1.22+)
- Patterns: `"GET /alive"`, `"GET /products/{id}"` (read with `r.PathValue("id")`), and `"POST /cart/items"`.
- `GET` also matches `HEAD`. A wrong method on a known path → **405** with an `Allow` header, for free. An unknown path → **404**.
- **Trailing slash rule:** `"/static/"` matches the whole subtree, and **`"/"` matches everything** (a catch-all). `"/{$}"` matches only the root. This matters on Day 4, when the frontend is served at `/`: more specific patterns win, so `/api/v1/...` routes still work.
- **Never** use `http.HandleFunc` / `http.ListenAndServe` (the package-level ones). They use a global mux and a server **with no timeouts**. Always create your own `http.NewServeMux()` and `&http.Server{...}`.

### 4. One goroutine per request
The server runs each incoming connection on its own goroutine, so **your handlers run concurrently**. Consequences:
- Never store per-request data in package-level or struct fields shared across requests.
- Shared things (logger, config, later the DB pool) must be safe for concurrent use. `*slog.Logger` and `*pgxpool.Pool` are.
- There's no `async/await`. A handler simply blocks on I/O, which is cheap in Go.

### 5. Timeouts: the defaults are dangerous
A zero-value `http.Server` has **no timeouts**. A client that opens a connection and sends 1 byte a minute (the "slowloris" attack) holds a goroutine and a socket forever. Know what each field covers:
- `ReadHeaderTimeout`: time to receive the request headers (the most important one).
- `ReadTimeout`: headers + body.
- `WriteTimeout`: from the end of reading the headers until the response is written.
- `IdleTimeout`: how long a keep-alive connection may sit unused.

Suggested values: 5s / 10s / 30s / 120s.

### 6. `context.Context`: cancellation flowing through the program
- A `Context` carries a **deadline or cancellation signal** (and request-scoped values) down the call chain. By convention it's the **first parameter**: `func Do(ctx context.Context, ...)`.
- `r.Context()` is cancelled when the client disconnects, when the handler returns, or when the connection is force-closed (`srv.Close()`). A **graceful** `Shutdown` does *not* cancel in-flight request contexts; it lets those requests finish. On Day 3 you'll pass it to DB queries, so abandoned requests stop their queries. This is the equivalent of C#'s `CancellationToken`.
- `signal.NotifyContext(ctx, os.Interrupt, syscall.SIGTERM)` gives you a context that's cancelled on Ctrl-C or `docker stop`. This is the trigger for shutdown.

### 7. Graceful shutdown: the exact sequence
1. Start `srv.ListenAndServe()` in a goroutine. It blocks until the server stops.
2. The main goroutine waits for **either** the signal context to be cancelled **or** `ListenAndServe` to return an error (for example, the port is already in use).
3. On a signal, call `srv.Shutdown(timeoutCtx)`. It stops accepting new connections, waits for active requests to finish, closes idle connections, and returns. Give it a deadline of ~10s.
4. `ListenAndServe` returns **`http.ErrServerClosed`** as soon as Shutdown *begins*. That's normal, **not** an error. **Trap:** don't exit when `ListenAndServe` returns. Exit only after **`Shutdown` itself returns**, or in-flight requests get killed. If the deadline expires, `Shutdown` returns `context.DeadlineExceeded` and leaves the remaining connections open. Call `srv.Close()` if you want to force them.

ASP.NET's `app.Run()` does all of this for you. In Go you write it once and understand it forever.

### 8. Configuration: env vars, typed once, fail fast
- Config comes from the environment (12-factor), so the same binary runs in dev, Docker, and production. This replaces `appsettings.json` + Aspire's injected `ConnectionStrings__storedb`.
- Read everything **once at startup** into a typed `Config` struct. Never call `os.Getenv` deep inside handlers.
- **Fail fast:** if `DATABASE_URL` is missing, exit immediately with a clear message, and report *all* missing variables at once (look up `errors.Join`).
- Testability trick: write `Load(getenv func(string) string)` instead of calling `os.Getenv` directly. In tests you pass a fake function. That's dependency injection with a plain function.

### 9. Structured logging with `slog`
- `logger.Info("server listening", "addr", ":5200")` produces key/value pairs, not string concatenation. A machine can filter them (`addr=:5200`).
- Choose the handler at startup: `slog.NewTextHandler` (readable, for dev) or `slog.NewJSONHandler` (for log collectors).
- Levels: Debug, Info, Warn, Error, set with `HandlerOptions{Level: ...}`. The C# `appsettings.json` uses `Information` as the default, so use Info.
- `http.Server.ErrorLog` takes an old-style `*log.Logger`. `slog.NewLogLogger(handler, slog.LevelError)` bridges it, so the server's internal errors go to your structured log too.

### 10. Dependency injection without a container
In C#, `builder.Services.Add...` registers types and the container builds them. In Go you **just build them in order and pass them in**:
```
cfg    := load config
logger := build logger from cfg
mux    := build routes, giving handlers what they need (logger, later services)
srv    := &http.Server{Handler: mux, ...}
```
That's the whole "container". It's explicit, checked at compile time, and has no magic. As things grow, you group dependencies in a struct (e.g. `type app struct{ cfg Config; log *slog.Logger }`) or pass them as function arguments (Mat Ryer style). Pick one style and stay consistent.

### 11. Why `main()` is tiny: the `run` pattern
```
func main() { if err := run(ctx, os.Getenv, os.Stdout); err != nil { print err; os.Exit(1) } }
```
- `os.Exit` and `log.Fatal` **skip deferred functions**, so cleanup (closing the DB pool later) wouldn't run. Inside `run` you only `return err`, and every `defer` runs.
- `run` takes its dependencies (env lookup, output writer) as arguments, which makes it **testable**.
- There's exactly one place where the process exit code is decided.

### 12. Packages and naming
- `cmd/store/main.go` and `cmd/admin/main.go` are each `package main`, so you get two binaries. `internal/config` is `package config`, importable only from inside your module.
- Name packages by **what they provide** (`config`, `httpx`), not `utils` or `common`. Avoid stutter: `config.Config` is fine, but `config.ConfigLoader` is not.
- Exported = Capitalized. Keep things unexported until another package needs them.

## D1.7 Common pitfalls (check yourself against these)
- Calling `w.WriteHeader` after `w.Write` gives the warning "superfluous response.WriteHeader call".
- Forgetting `return` after writing an error response, so the handler keeps going and writes twice.
- Treating `http.ErrServerClosed` as a failure, so every clean shutdown exits with code 1.
- Calling `log.Fatal` / `os.Exit` inside `run`, so the defers are skipped.
- Using `http.DefaultServeMux` or `http.ListenAndServe`: a global mux and no timeouts.
- Registering `"/alive/"` (with a slash), which matches a subtree you didn't intend.
- Reading `os.Getenv` all over the code instead of once in `config`.
- An unbuffered error channel that the server goroutine blocks on forever after shutdown (a goroutine leak). Use a buffer of 1.
